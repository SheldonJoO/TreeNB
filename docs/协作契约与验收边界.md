# TreeNB 协作契约与验收边界

更新日期：2026-11-28

## 1. 目的

本文约定 TreeNB 的修改、验证、发行和在线服务交付边界。目标是把“代码已改”“构建成功”“真机可用”“服务已上线”分开证明，避免用其中一项冒充另一项。

## 2. 不可破坏的产品约束

1. 两条签名路径必须同时成立：
   - 电脑侧载使用过的 Apple ID 证书可以原样导入 TreeNB 复用，不吊销、不重新签发。
   - 手机可切换到另一个 Apple ID，使用该账号独立保存的凭据、团队、证书、私钥和 anisette 状态签名。
2. 多 Apple ID 状态按账号隔离持久化。切换账号是激活已保存状态，不是重新登录；不得因切换团队或账号清空其他账号材料。
3. 不自动吊销用户证书。证书已满时必须由用户明确选择吊销对象。
4. UI 基线是“0419 全屏 + 0828 玻璃拟态 v3”：禁止上下黑边、禁止闪屏遮罩、禁止跳过引导页。
5. 顶栏左侧只保留列表图标，其余功能收进右侧 `⋯` 菜单。文案统一使用“支持与动力”。
6. 主 App 保持 iOS 15 兼容。仅 iOS 16 及以上可用的 API 必须有明确的可用性门禁。
7. 日志、截图和反馈邮件不得记录 Apple ID 密码、2FA、p12 内容、私钥、Token、完整配对文件或 anisette 秘密。
8. Open Minis 已从 App Store 下架，只提醒一次；免电脑安装流程继续服务已安装用户，不删除流程。

## 3. 事实来源与文档优先级

出现冲突时按以下顺序判断：

1. 当前工作树源码、构建脚本和可复现的设备日志。
2. 当前版本的 Release、CI 产物和 SHA256。
3. 已标记为“已实施 / 已验证”的协议与验收记录。
4. 历史设计、交接说明和记忆。

历史设计可以解释动机，不能覆盖当前实现。文档必须标明日期和状态：`草案`、`已接受`、`已实施`、`已验证`。只有真机或线上证据满足对应条件时，才能使用“已验证”。

## 4. 修改流程

### 4.1 先取证再修改

- 用户报告的问题、操作步骤和截图是验收输入，不得要求用户反复自证。
- 至少确认触发入口、完整调用链、失败状态和现有恢复行为。
- 对启动、签名、安装和账号切换问题，必须跨层审计；不能只修改提示文案。
- 对无法复现的真机问题，先增加脱敏诊断，再依据日志决定修复位置。

### 4.2 最小修复

- 优先修改现有文件和现有链路，不引入与问题无关的重构、抽象或兼容层。
- 不增加无法触发的兜底；外部输入、下载包、磁盘文件和系统 API 返回值必须在边界校验。
- 修复必须说明根因、改动文件、验证方式和残余风险。
- 如果修复涉及安全审查发现项，按安全审查结果处理，不把“继续发布”当成默认授权。

### 4.3 验证分层

| 层级 | 必须证明 | 不能冒充 |
|---|---|---|
| 静态检查 | shell/Python/JavaScript/YAML 语法、资源引用、清单一致性 | App 能运行 |
| 离线回归 | 状态迁移、错误分支、解析与校验逻辑 | 真机签名安装成功 |
| CI 构建 | Xcode 26 编译、Archive、IPA 组装、dSYM、UUID、SHA256 | 所有设备和签名账号可用 |
| 真机验收 | 指定设备、系统、账号和操作路径实际通过 | 其他组合必然通过 |
| 线上验收 | 外网 HTTPS、文件字节、JSON、下载和校验通过 | App 内更新客户端已实现 |
| 发行验收 | Release 资产与 CI 产物一致、说明和回滚路径完整 | 产品所有历史问题已消失 |

## 5. 构建与发行契约

### 5.1 固定构建链

- 使用 GitHub Actions `macos-26` 和 Xcode 26，不切换到 Xcode 27。
- 链接保留 `-ld_classic`，用于兼容 ring 预编译汇编 object。
- Scheme 固定为 `TreeNB-App`。
- Archive 为 unsigned；安装时由当前账号在本机重签。
- 每次交付同时检查主程序与 dSYM UUID，不能只检查文件是否存在。

### 5.2 构建标识

- 版本号使用真实构建时间戳：`YYYYMMDDHHMM`。
- IPA 文件名：`TreeNB-YYYYMMDDHHMM-unsigned.ipa`。
- 交付副本：`TreeNB-YYYYMMDDHHMM.ipa`。
- 桌面目录统一为 `~/Desktop/侧载测试/`，并用 `touch -t` 同步文件时间。
- 每个构建交付可点击的 `file://` 链接和 SHA256。

### 5.3 发布顺序

1. 完成实现、离线验证和所需安全审查。
2. 提交或固定待发行源码。
3. 运行 Xcode 26 CI，核对 commit SHA、Archive、IPA、dSYM UUID 与 SHA256。
4. 创建 GitHub Release，上传 IPA、dSYM、校验和及必要的引导引擎。
5. 外部下载 Release 资产并复核字节数和 SHA256。
6. 发布安装站和版本化更新清单，外部验证后再切换 `latest.json`。
7. 按设备矩阵做真机回归；未完成的矩阵必须明确列为待验，不能写“全部通过”。

## 6. 在线安装与更新边界

- 发布站只托管静态页面、引导脚本、unsigned IPA 和更新清单。
- 发布站不接收、不代理、不保存 Apple ID 密码、2FA、证书、私钥、UDID、完整配对文件或 anisette 数据。
- 免电脑安装的凭据只在本机用于登录 Apple 和签名；TreeNB 发布站不是凭据接收方。
- 更新安装模式固定为 `resign_and_install`：App 下载并校验后，使用当前账号既有证书在本机重签安装。
- 下载包必须校验字节数和 SHA256；解压后还要校验 bundle ID、最低系统、arm64 Mach-O、路径穿越和符号链接逃逸。
- 没有清单签名前，不提供静默安装。后续启用自动更新前必须加入发布方身份签名。
- 1307 已具备更新清单和发布源，但不包含 App 内更新客户端；下一版客户端通过验收后才能宣称 App 内更新可用。
- 正式协议见 `docs/在线更新服务协议.md`。

## 7. 诊断与反馈边界

- guest 启动错误使用独立持久化日志，与主壳签名错误分开。
- 日志按文件大小轮换，单文件上限 512 KB；只保留排查所需字段。
- 错误反馈必须让用户确认预览后再发送；邮件正文只包含脱敏诊断和用户补充说明。
- 反馈邮箱固定为 `zhuxiandong@gmail.com`。
- 内置错误文档要区分“已知错误”“可能原因”“验证方法”和“仍无法解决时的反馈入口”。

## 8. 文档纪律

同一改动涉及行为、构建、发布或用户操作时，必须同步更新对应文档：

- 源码行为变化：更新架构或启动链说明。
- 构建工具链变化：更新 README、CI 说明和踩坑记录。
- 安装地址或安装步骤变化：同步根安装页、README 和引导脚本。
- 更新协议变化：更新版本化协议，并说明旧客户端兼容边界。
- 已知限制变化：更新验收矩阵，不把待验证项写成已完成。

不得只改文档让描述看起来通过，也不得只改代码而保留旧的发布说明。历史设计如与现状冲突，应加“已被现状取代”的说明，而不是静默删除证据。

当前必须持续保持的事实边界：

| 文档或入口 | 当前正确事实 |
|---|---|
| App 内在线更新 | 1307 只有服务端清单，客户端尚未实现 |

## 9. 真机验收矩阵

每版至少覆盖以下路径；实际设备、系统和 Apple ID 组合记录在交付说明中。

| 路径 | 最低验收点 |
|---|---|
| 全新安装 | 引导页不跳过；无上下黑边；首次账号状态可保存 |
| 已装升级 | 旧 App 数据、账号保险库和 guest 数据保留 |
| 多账号切换 | A 切 B 再切 A，无需重登；团队与证书归属正确 |
| 电脑证书复用 | 原样导入；不吊销、不重签；可执行签名安装 |
| 手机独立签名 | B 账号使用 B 的团队和证书；不影响 A |
| 证书已满 | 停止自动吊销；用户勾选后才重试 |
| 安装失败 | 错误码与脱敏日志可定位；不清空已保存材料 |
| guest 冷启动 | 容器内点击、小组件、深链均进入正确 guest |
| guest 启动失败 | 不闪回无提示；保留宿主可用并展示独立错误 |
| 返回主壳 | 不进入错误账号、不误开旧 guest、不丢当前选择 |
| iOS 15 | 启动、基础签名和容器入口不因高版本 API 崩溃 |
| iOS 26 | Liquid Glass 与全屏基线同时成立 |
| iOS 27 免电脑 | Open Minis、LocalDevVPN、配对、签名、安装全流程通过 |

## 10. 完成定义

只有以下条件全部满足，任务才能标记完成：

- 需求中的每条路径都有对应实现或明确的不可实现说明。
- 修改文件经过静态检查和必要的离线回归。
- 构建产物有真实时间戳、UUID、SHA256 和桌面交付。
- 安全审查按当前变更集执行并处理结果。
- 真机未验证的部分明确保留为待验，不提前关闭。
- 文档、安装页、更新清单和 Release 对同一版本给出一致事实。
- 线上服务经过外网验证；DNS、证书或托管未完成时，只能报告“本地就绪”或“临时地址可用”，不能报告正式域名已上线。
