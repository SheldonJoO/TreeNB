# TreeNB 在线更新服务协议 v1

## 1. 当前边界

- 正式检查地址：`https://TreeNB.idoer.help/updates/latest.json`。
- 1307 对应版本清单：`https://TreeNB.idoer.help/updates/v1.4.6.json`。
- 下载地址：`https://TreeNB.idoer.help/downloads/TreeNB-202611281307-unsigned.ipa`。
- 服务只托管版本清单和未签名 IPA，不接收 Apple ID、密码、2FA、证书、私钥、UDID 或 anisette 数据。
- 1307 尚未包含 App 内更新客户端。下一版必须按本协议接入后，才能宣称支持 App 内更新。
- 清单通过 HTTPS 分发，SHA256 用于完整性校验，不等同于发布方身份签名。

## 2. 清单字段

| 字段 | 规则 |
|---|---|
| `schemaVersion` | 当前为 `1`；不兼容变更必须升版本 |
| `channel` | 当前只发布 `stable` |
| `bundleIdentifier` | 必须严格等于 `com.openssai.app` |
| `version` | 展示版本，当前 `1.4.6` |
| `build` | 单调递增的构建号；当前 `202611281307` |
| `minimumOSVersion` | 安装包实际支持的最低系统，当前 `15.0` |
| `releasedAt` | ISO 8601 带时区时间 |
| `mandatory` | 是否强制更新；服务端不得仅凭此字段绕过用户确认 |
| `installMode` | 当前为 `resign_and_install`，由客户端本机重签安装 |
| `packageType` | 当前为 `unsigned_ipa` |
| `downloadUrl` | 只允许 HTTPS；客户端还要校验最终重定向主机 |
| `sha256` | 下载文件的完整 SHA256，小写十六进制 |
| `size` | 文件字节数，用于拒绝截断和异常响应 |
| `releaseUrl` | 对应 GitHub Release，供用户查看完整说明 |
| `notes` | 面向用户的更新说明数组 |

## 3. 客户端接入要求

下一版 App 至少实现以下流程：

1. 手动或按用户设置检查更新；首次不静默下载大文件。
2. 仅接受 HTTPS，校验 bundle ID、JSON 结构、版本和 build；build 不高于当前版本时不提供升级。
3. 当前系统低于 `minimumOSVersion` 时隐藏升级按钮并说明原因。
4. 展示版本、更新时间、更新说明、包大小和“将使用当前 Apple ID 重签”的提示，由用户确认。
5. 下载到临时目录，校验字节数和 SHA256；不一致时删除文件并终止。
6. 解压检查 `Payload/*.app/Info.plist`：bundle ID 必须一致，最低系统不得高于当前系统，主程序必须是 arm64 Mach-O；拒绝路径穿越、符号链接逃逸和异常大的条目。
7. 使用当前已激活账号的既有证书重签并安装。不得自动吊销证书，不得要求重新输入已保存账号的密码，不得把材料上传服务器。
8. 安装失败保留旧 App 和所有账号数据；清理临时文件，展示现有错误排查入口。
9. 安装成功后由用户决定立即打开；记录脱敏结果日志，不记录密码、Token、p12 或私钥。

## 4. 发布纪律

- 先完成 CI、IPA/dSYM UUID 核对、SHA256 计算和安全审查，再创建 Release。
- 发布站文件必须与 Release 中的 IPA 字节一致，不允许重新打包或二次压缩。
- 先上传 IPA 和版本清单，再从外部网络验证 HTTP 状态、JSON、字节数和 SHA256，最后切换 `latest.json`。
- 回滚时发布更高 build 的修复包；不得把 `latest.json` 指向已撤下或校验失败的旧文件。
- 域名、DNS 或证书故障时保留 GitHub Release 作为下载回退，不能宣称更新服务可用。

## 5. 后续安全升级

在 App 内自动更新正式启用前，应增加 Ed25519 清单签名：私钥由发布者离线保管，公钥随 App 发布；客户端验证签名后才读取下载地址。未完成签名验证前，只能提供“用户确认后下载”，不得静默安装。
